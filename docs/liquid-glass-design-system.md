# Liquid Glass 改造规划

这次改造不是给所有容器统一加透明背景，而是重新梳理内容层和操作层。游戏封面、说明、设置项等内容保持稳定、清晰；导航、工具栏、菜单、Sheet 和 HUD 作为独立功能层浮在内容上。

## 设计原则

1. **内容优先**：玻璃只用于主要交互和导航，不用于普通内容卡片。
2. **单一功能层**：相邻控件共享一块玻璃，不堆叠多个模糊层。
3. **形状有来源**：圆角跟随屏幕、封面或父容器的几何关系，避免无差别大圆角。
4. **触摸有物理反馈**：按下立即收缩并提亮，松开保留速度回弹；状态切换使用形变，不只做淡入淡出。
5. **自适应可读性**：亮暗主题分别定义染色、高光、描边和阴影，文字与图标继续使用语义色。
6. **性能是样式的一部分**：模糊区域必须有裁剪；游戏画面上的控件默认允许关闭实时模糊；滚动内容中不放 BackdropFilter。
7. **尊重减少动态效果**：系统关闭动画时，控件直接切到终态。

## 材质层级

| 层级 | 组件 | 材质 |
| --- | --- | --- |
| 内容层 | 游戏封面、详情、设置列表、说明卡片 | 实色或标准 surface，不使用玻璃 |
| 常驻操作层 | 顶部工具栏、底部导航、搜索 | `UiGlassVariant.clear` |
| 强可读浮层 | 菜单、Bottom Sheet、Dialog | `UiGlassVariant.regular` |
| 游戏 HUD | 调试信息、暂停与退出控制 | clear/regular 染色，可关闭实时 blur |

## Token 与组件

- `UiGlassTheme`：亮暗主题下的 fill、pressed fill、border、highlight、shadow、blur sigma。
- `UiGlassSurface`：唯一的玻璃绘制入口，负责裁剪、模糊、染色、高光和阴影；HarmonyOS 默认使用无实时 blur 的稳定材质。
- `UiGlassToolbar`：让一组相邻操作共享同一块材质与一次背景采样。
- `UiGlassIconButton`：44pt 点击区、真实弹簧按压、触感反馈、减少动态效果支持。
- `UiSprings`：集中维护按压和 materialize 的物理参数。

## 页面迁移顺序

### 1. 基础组件与导航操作

- [x] 玻璃主题 token
- [x] Surface / Toolbar / Icon Button
- [x] 首页右上角操作合并为单一玻璃工具栏
- [ ] 页面返回按钮统一使用玻璃按钮
- [ ] 标题栏滚动边缘效果与内容穿行

### 2. 浮层

- [x] `UiContextMenu` 从触发控件原位 materialize，并按空间自动选择方向
- [ ] `UiBottomSheet` 使用 regular 材质；大尺寸 Sheet 保持更厚、更稳的视觉
- [ ] `UiDialog`、Snackbar、Toast 统一出现/消失节奏
- [ ] 避免菜单、按钮、Sheet 之间的玻璃重叠

### 3. 高频控件

- [ ] Button、Switch、Segmented、Slider、Search 的按压与状态形变
- [ ] 输入框聚焦、高亮和错误态
- [ ] 统一 44pt 最小点击区、图标尺寸和控件间距

### 4. 页面结构

- [ ] 首页：内容延伸到工具栏后方，大标题归入内容流
- [ ] 游戏详情：封面背景延伸，返回/启动操作形成清晰的浮动功能层
- [ ] 设置：导航层浮起，列表继续使用实体 grouped surface
- [ ] 元数据选择：统一搜索、选择和确认动作层级

### 5. 游戏界面

- [ ] HUD 与右上角控制菜单复用 glass token 和 spring
- [ ] 游戏运行时禁用大面积实时模糊，只保留小面积、可裁剪的材质采样
- [ ] 展开、反向打断、屏幕旋转和连续点击真机验证

## 验收清单

- 亮色、暗色和跟随系统主题下均可读。
- 文字放大后不截断，所有交互目标至少 44×44pt。
- 开启“减少动态效果”后不再运行弹簧过程。
- 90/120Hz 等不同系统刷新率下按压和形变无固定帧率假设。
- 真机检查首页滚动、菜单连续开合、Sheet 拖拽和游戏运行帧率。
- GPU 性能回归时优先关闭游戏 HUD blur，不牺牲游戏画面帧率。
